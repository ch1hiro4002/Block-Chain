# Block-Chain

一个使用 Go 编写的轻量级、教学向区块链节点。项目重点演示常见的区块链概念：签名交易、交易池、区块构建与验证、类 P2P 消息广播，以及一个带有内存键值状态的小型栈式虚拟机。

> 该项目不适合生产环境，主要用于学习 Go 并发、接口设计和区块链基础机制。

## 功能特性

- 基于 ECDSA P-256 的密钥生成、交易签名和签名验证
- 支持重复交易检测和最大容量限制的交易池
- 使用 SHA-256 哈希连接区块，并进行区块验证
- 验证者节点定时创建新区块
- 基于内存的本地传输层和消息广播
- 简单栈式虚拟机，支持整数、字节打包、算术运算和状态读写
- 针对 core、network、crypto 包的单元测试

## 环境要求

- Go 1.26+

## 快速开始

构建并运行：

```bash
make build
make run
```

运行测试：

```bash
make test
```

演示程序会启动多个通过本地传输层连接的进程内节点。一个远端节点会持续向本地验证者节点发送签名交易，验证者节点将交易加入交易池，并定时创建新区块。

## 主要组件

### 交易

交易包含：

- `Data`：交易负载，当前被当作虚拟机字节码执行
- `From`：发送方公钥
- `Signature`：针对 `Data` 的签名

交易进入交易池前会进行验证，并记录本地首次看到时间。

### 区块

区块包含区块头、交易列表、验证者公钥和区块签名。区块头包括：

- 版本号
- 交易数据哈希
- 前一区块哈希
- 时间戳
- 高度

### 区块链

`core.BlockChain` 在内存中保存区块头，并在写入前验证新区块。当前存储实现只存在于内存中，不会持久化。

### 网络层

`network.Transport` 是消息传输抽象。当前实现为 `LocalTransport`，使用 channel 和 Go map 连接进程内节点。

消息使用 `encoding/gob` 编码，可以携带交易或区块。

### 虚拟机

虚拟机将交易的 `Data` 当作简单字节码流执行，并维护一个栈和共享内存状态。

当前指令集：

| 操作码 | 指令 | 栈行为 |
| --- | --- | --- |
| `0x0a` | `InstrPushInt` | 将前一个字节作为 `int` 入栈 |
| `0x0b` | `InstrPushByte` | 将前一个字节作为 `byte` 入栈 |
| `0x0c` | `InstrAdd` | 弹出 `a`、`b`，压入 `a + b` |
| `0x0d` | `InstrSub` | 弹出 `a`、`b`，压入 `b - a` |
| `0x0e` | `InstrMul` | 弹出 `a`、`b`，压入 `a * b` |
| `0x0f` | `InstrDiv` | 弹出 `a`、`b`，压入 `b / a`；`a == 0` 时返回错误 |
| `0x10` | `InstrPack` | 弹出 size，再弹出 size 个字节并打包为 `[]byte` |
| `0x11` | `InstrStore` | 弹出 key 和 value，写入状态 |
| `0x12` | `InstrGet` | 弹出 key，压入对应状态值 |

字节码格式被刻意设计得很简单。立即数位于对应操作码之前，例如：

```text
0x03 0x0a   将整数 3 入栈
0x02 0x0a   将整数 2 入栈
0x0c        加法 -> 5
```

## 演示流程

1. 一个远端传输层持续创建签名交易并发送给本地服务端。
2. 本地服务端验证交易，加入交易池并广播。
3. 本地验证者按定时器运行，从待处理交易中创建签名区块。
4. 区块经过验证后由虚拟机执行，保存到内存，并广播给对端。
5. 其他节点验证并将区块写入本地链。

## 当前限制

- 网络传输仅限本地内存，没有真实的 TCP 网络或节点发现。
- 区块链和状态不会持久化到磁盘。
- 共识机制简化为单个验证者，没有分叉解决或多验证者共识。
- 虚拟机功能有限，没有 gas、执行限制或完整的运行时安全检查。
- 区块头尚未包含状态根或收据根。
- 项目仅用于学习和演示，不可用于生产或金融场景。

## 后续改进方向

- 增加真实的 TCP 或 HTTP 传输层
- 使用数据库持久化区块链和状态
- 增加状态根/收据根验证
- 在远端节点收到区块后清理已确认交易
- 增加 gas 计量和更完善的虚拟机错误处理
- 增加节点发现和多验证者共识
